# 锁与内存深化规划（面向 SoC 音视频编解码岗）

> 适配你的岗位：SoC 端音视频编解码、播放器/录屏适配、性能调优、可能接触驱动/内核。

## 1. 先说你工作里最常见的“锁+内存”问题

1. 线程问题（锁）
   1. 队列背压导致上游阻塞，表现为卡顿/延迟抖动
   2. 线程退出不干净，表现为 stop 后迟迟不退出
   3. 多把锁顺序不一致，出现偶发死锁
   4. 配置更新与数据线程并发，出现参数生效不一致
   5. 过度使用自旋导致 CPU 飙高

2. 内存问题
   1. 帧缓冲频繁分配释放导致抖动与碎片
   2. 首次触页(page fault)导致首帧慢
   3. 队列过深导致“吞吐不变但延迟升高”
   4. 对齐不当影响 DMA/SIMD 路径
   5. 零拷贝路径没打通，内存带宽被 memcpy 吃掉

## 4. 结合岗位的“高频技术判断题”

1. 自旋锁什么时候用？
   1. 临界区极短，且线程不应睡眠的路径
   2. 用户态一般优先 mutex/rwlock，spin 是少数特例

2. 码控参数动态更新怎么做更稳？
   1. 控制面写参数（低频）+ 数据面读参数（高频）
   2. 参数生效常绑定关键帧边界，避免画面异常

3. 低延迟直播为何会主动丢帧？
   1. 因为“追实时性”优先于“绝对完整性”
   2. 否则队列排队时延会持续增长

4. 为什么你必须会内存池？
   1. 大帧反复 malloc/free 容易抖动
   2. 池化可降低分配开销并稳定时延
