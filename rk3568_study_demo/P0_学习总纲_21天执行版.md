# RK3568 SoC 音视频 P0 学习总纲（21 天执行版）

更新时间：2026-04-25  
适用对象：SoC 音视频编解码/软件/驱动方向工程师（你当前岗位）

## 1. 文档目的

1. 把“零散学习”改成“可执行的训练计划”。
2. 把“会写 demo”升级为“能做故障闭环”。
3. 用统一标准验收学习成果，避免学了但无法落地。

## 2. P0 最终目标（必须达到）

1. 能独立完成采集 -> 编码/解码 -> 封装/推流 -> 播放链路的性能与稳定性定位。
2. 遇到首帧慢、尾延迟抖动、队列堆积、A/V 不同步、偶发卡顿时，可在 1 天内给出：
   现象 -> 指标 -> 根因 -> 修复 -> 回归结果。
3. 形成可复用资产：
   `phase1_report.md`、`run_phase1.sh`、`phase1_metrics.csv`、排障 checklist。

## 3. 能力等级定义（每个主题都按此验收）

1. L1 知识级：知道概念，能解释术语。
2. L2 实操级：能独立编译运行、改参数、读输出。
3. L3 闭环级：能定位问题并给出可验证修复（P0 目标）。
4. L4 负责人级：能制定规范、做架构取舍、带队推进。

## 4. P0 全量学习地图（你“所有所有所有”要学的内容）

## 4.1 并发与同步（P0）

1. 线程模型：生产者-消费者、流水线并发、线程生命周期。
2. 锁模型：mutex/rwlock/spinlock 适用边界。
3. 原子与内存序：relaxed、release/acquire、seq_cst。
4. 条件变量：等待/唤醒、虚假唤醒、防丢信号。
5. 停机协议：stop + close + join 的工程模板。
6. 死锁规避：统一锁序、lock rank、超时锁策略。

学到程度（L3）：
1. 你能判断“正确性问题”还是“性能问题”。
2. 你能解释为什么某段代码用 atomic 不用 mutex。
3. 你能写出线程安全、可退出、可压测的并发模块。

## 4.2 指标体系与观测（P0）

1. 指标：avg/p95/p99/max、deadline miss、drop、queue depth、wait time。
2. 采集：每秒窗口统计、阶段时间戳、队列峰值。
3. 归因：均值优化 vs 长尾优化。
4. 输出：可对比表格、趋势图、回归基线。

学到程度（L3）：
1. 不再只看平均值，能解释“体感卡顿”为何由 p99/max 主导。
2. 能输出可复现数据报告而不是口头结论。

## 4.3 内存系统与实时性（P0）

1. page fault：minor/major fault 与首帧慢。
2. 分配模式：on-demand vs prealloc。
3. 预热策略：prefault、mlock 与限制条件。
4. 池化：固定缓冲池、所有权边界、回收闭环。
5. 抖动治理：减少热路径分配、控制长尾。

学到程度（L3）：
1. 能把实时抖动定位到具体内存路径。
2. 能用数据证明预分配/池化的收益（尤其 p99/max）。

## 4.4 Cache 与数据布局（P0）

1. 缓存局部性：顺序访问与随机访问差异。
2. 伪共享：cache line bouncing 的根因。
3. 结构体布局：padding、alignas、热字段隔离。

学到程度（L3）：
1. 你能在代码评审时主动识别伪共享风险。
2. 你能提出低侵入修复并验证吞吐改善。

## 4.5 零拷贝与 DMA 流水线（P0）

1. copy path 成本模型：CPU 带宽与缓存污染。
2. zero-copy 基本思路：句柄/引用传递替代 memcpy。
3. 双缓冲/多缓冲：吞吐、延迟、内存占用的平衡。
4. 瓶颈定位：cpu_wait、dma_wait、max_filled_depth。

学到程度（L3）：
1. 能画出链路拷贝拓扑并给出“先砍哪次拷贝”。
2. 能给出 buffer 数量的工程选型理由。

## 4.6 音视频数据与编码基础（P0）

1. 视频：YUV/RGB、stride/align、色度采样、FourCC。
2. 编码：GOP、IDR、码率控制、QP 与画质波动。
3. 音频：采样率、帧长、重采样、缓冲欠载/过载。
4. 时间戳：PTS/DTS、A/V 同步、时钟漂移治理。

学到程度（L3）：
1. 能快速判断格式错配、时间戳异常、码控不稳的根因方向。
2. 能给预览、直播、录制三类场景定策略模板。

## 4.7 Linux 多媒体栈与驱动接口（P0，阶段后续延展）

1. 用户态：FFmpeg/GStreamer/MPP 调用链。
2. 内核态：V4L2/vb2、Media Controller、ALSA、DRM/KMS。
3. 共享缓冲：dma-buf、CMA、IOMMU、一致性边界。
4. 调试工具：perf/ftrace/procfs。

学到程度（L3）：
1. 能把用户态现象映射到驱动层嫌疑路径。
2. 能和驱动同学对齐 buffer 生命周期和同步语义。

## 5. 第 1 阶段执行计划（21 天，超详细）

说明：
1. 本阶段只做 P0 基础闭环，不扩散到太多新框架。
2. 每天固定节奏：学习 1.5h + 实验 2h + 总结 1h + 复盘 0.5h。
3. 每天必须产出一个 `DayX Report`。

### Day 1：竞态与正确性基线
1. 主题：NO_LOCK/MUTEX/ATOMIC 正确性边界。
2. 命令：
```bash
g++ -std=c++11 -O2 -pthread week_02_锁_竞态与互斥.cpp -o d1_lock
./d1_lock 8 500000 3
```
3. 重点指标：expected、actual、lost_updates、throughput。
4. 通过标准：能解释丢更新根因与修复方式。

### Day 2：原子操作与内存序
1. 主题：relaxed 与 release/acquire 的正确用法。
2. 命令：
```bash

./d2_atomic 8 400000 200000
```
3. 重点指标：不同内存序吞吐对比、发布订阅错误数。
4. 通过标准：能写出一个无竞态发布-订阅示例并自解释。

### Day 3：锁选型实战
1. 主题：自旋锁与互斥锁在不同临界区下的差异。

### Day 4：背压定位
