# V4L2 14 天学习路线（执行版）

## 1. 路线目标

14 天后你要达到：

1. 能独立写出 `open -> QUERYCAP -> S_FMT -> REQBUFS -> QBUF/DQBUF -> STREAMON/OFF` 的采集程序。
2. 能解释每个关键 `ioctl` 的前置条件、关键字段、常见错误。
3. 能把“能跑”升级为“可验证”：输出 fps、丢帧、超时、错误码统计。
4. 能对接你当前 RK3568 项目，明确下一步如何进入 `DMABUF` 和多媒体链路。

## 1.1 Codec 双环境提醒

14 天 V4L2 采集路线之后，进入 codec/M2M/hwaccel 时按双环境执行：

1. VM：学习 V4L2 M2M 逻辑和虚拟节点实验，只证明 ioctl/state machine。
2. RK 板：验证真实硬件编解码，当前主线是 RKMPP，例如 `h264_rkmpp/hevc_rkmpp`。
3. 如果 RK 板没有 V4L2 M2M codec 字符设备，不要把 camera/ISP 节点当 codec 节点。

完整说明见：

```bash
less /usr/local/MPP_DEMO/rk3568_study_demo/v4l2/learning_plan/00_dual_environment_codec_route.md
```

## 2. 两阶段安排

1. 第一阶段（Day01-Day07）：打牢采集基础
   - 节点识别、格式协商、MMAP 队列、单帧/连续帧、控制项、错误恢复。
2. 第二阶段（Day08-Day14）：走向工程化
   - 像素格式、多线程、性能指标、Media Controller、DMABUF 概念、综合实战。

## 3. 每天固定节奏（建议）

1. 理论阅读 45 分钟（只读当天指定页面）。
2. 动手实验 90 分钟（命令 + 代码）。
3. 记录复盘 30 分钟（结果、问题、结论）。

## 7. 失败处理规则

1. 当天卡住超过 40 分钟：先用 `v4l2-ctl` 验证，再回代码。
2. 不确定节点类型：先 `v4l2-ctl --all`，确认 `Video Capture` 再写代码。
3. 出现随机失败：优先记录 errno 和触发步骤，不盲改。
